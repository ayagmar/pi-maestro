## Direction findings deferred (recorded, no plan yet)

- **Non-interactive / CI drive mode**: high adoption value; building blocks exist (text
  fallbacks, `doctor cleanup confirm` precedent, deterministic preflight, bounded summaries).
  Needs a design spike on which gates may auto-accept.
- **Dashboard as floating overlay**: `ctx.ui.custom(..., { overlay: true })` would keep the
  transcript visible; API marked experimental — prototype-gated.
- **Prompt-template/skill packaging** via `resources_discover`: LOW confidence it beats the
  command UX — spike only.
- **Dependency wave visualization** in the board: data exists (simulate's waves); value scales
  with plan size.
- **Live per-task cost in board rows**: needs a `liveRuns` accessor on `DashboardActions`; do it
  on top of plan 003's snapshot.
- **Attempt-compare + bounded report modal** (from counterpart's evidence-viewer ambition):
  follow-up after plan 008.

## Findings considered and rejected

- Hardcoded ANSI colors: none — src consistently uses `theme.fg` (92 sites).
- Custom tool renderers missing: false — `src/tools.ts:237-544` already implements
  renderCall/renderResult well.
- Doc/behavior drift: unusually well-guarded by `test/docs.test.ts`; no live drift found.
- Failure-path message quality in runner/workflow/worktree: exemplary — not a finding.
- `planGate` defaulting to false: deliberate, documented preset choice with cost-cap backstops.
- Transcript memory growth: bounded (`MAX_ITEMS=400`, incremental tail).
- Replacing the dashboard grid with pi-tui `SelectList`: SelectList is 1D; the grid needs custom
  navigation.
- Web UI / React frontend before release (counterpart, concurred): second rendering stack, not
  needed for the actual friction.
- New model-facing plan-inspection/approval tool (counterpart, concurred): approval is a human
  trust boundary; keep it slash-command/dashboard only.
- Changing `cleanupCompletedTasks` default (counterpart, concurred): fix discoverability first
  (plan 009), then revisit with real feedback.
